# Vertical Positioning

This doc translates the canonical spec into department-specific proof.

Use it when the buyer is a department lead, not a generic platform buyer.

## Customer Success

### Daily pain

- Open CRM, support, billing, and chat before the first standup
- Manually assemble account health from scattered sources
- Prepare QBRs over 4+ hours of copy-paste work
- Miss churn signals because risk data lives in the wrong system
- Loses context when an account transfers to another CSM

### What IntegrateWise delivers

- One account view with relationship history, commitments, health signals, and next actions
- Meeting brief prepared before the user opens it
- Silent signal on account risk with supporting evidence
- Draft follow-up and customer response, reviewable before sending
- Handover context that travels with the account, not the person

### Measurable shifts

- QBR prep:Hours → minutes
- Time-to-risk visibility: multi-system ritual → one Workbench check
- Handover time: manual file assembly → transfer-ready context
- Expansion capture: signals across usage, tickets, billing, conversation → one decision

### Key proof points

- Designed for multi-system account health
- Twin prepares, user decides
- Every prepared item is reviewable before it executes

### What IntegrateWise delivers

- One pipeline view that respects revenue stageswhile keeping operational truth
- Signal when a deal goes silent or budget language shifts
- Renewal or expansion indicators surfaced across contracts, usage, and conversations
- Draft outreach prepared from real account context
- Approval trail if exec updates, outreach, or proposals should go out

### Measurable shifts

- Forecast accuracy: disconnected signals → evidence-backed stage

- Rep capacity: prep time reclaimed for selling

- Compliance-visible governance on any customer-facing action

- Duplicate records and schema drift across systems

### What IntegrateWise delivers

- Unified, governed truth across connected tools
- Entity360 that normalizes field meaningwithout changing source ownership
- Twin reasoning over assembled context instead of manual spreadsheets
- Capability fabricthat lets you define once and surface anywhere
- Swappable connectors and models without changing product logic

### Measurable shifts

- Reporting latency: hours → minutes
- Duplicate recovery time: manual cleanup → governed resolution with human review

- Data trust: “version 3 of the dashboard” → single source with provenance

### Key proof points

- No model owns your operational truth.
- Every field carries source attribution and confidence.

## Engineering / Platform

### Daily pain

- Point-to-point integrations multiply as the company grows
- Each team rebuilds auth, normalization, error handling, and retry logic
- Lock-in to a vendor’s model, credential model, or experience layer
- Compliance and governance bolted on after the fact
- Observability split across infrastructure and business outcomes

### What IntegrateWise delivers

- Connector path: connect once, hydrate forever
- Capability Contract layer keeps business logic out of infrastructure code
- Governance gates before execution, not after
- Approval-gated memory: propose → review → promote
- Audit trail by design: proposal, approval, execution, sync, promotion

### Measurable shifts

- Integration effort: weeks per system → enable toggle per system
- Incident response: hunting across logs → Timeline event ancestry
- Compliance surface area: bolt-on → built-in via pre/post proposal gates
- Cognitive load: build and maintain → use and govern

### Key proof points

- No connector ever writes directly to the Spine.
- Every byte has an owner. Every store has a purpose.
- No product plane depends on a provider primitive.
