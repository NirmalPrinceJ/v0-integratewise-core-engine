THE CHALLENGE
─────────────────────────────────────────────────────────────────────────────

Traditional approach (BROKEN):
  Sales workbench shows only sales data → Rep has no idea if account is healthy
  CSM workbench shows only CSM data → CSM can't see if Sales has new opportunities
  Finance workbench shows only finance data → Finance team can't see churn risk

Reality (HOW ORGS ACTUALLY WORK):
  Sales rep needs: Deal (primary) + Account health + Contract terms + Support tickets
  CSM needs: Account health (primary) + Sales upsells + Finance MRR + Support SLA
  Finance needs: Invoices (primary) + Sales pipeline + Churn risk + Payroll

═══════════════════════════════════════════════════════════════════════════════

THE SOLUTION: ORGANIZATIONAL CONTEXT BRIDGE
─────────────────────────────────────────────────────────────────────────────

Each workbench is SPECIALIZED but INTERCONNECTED:

PRIMARY DOMAIN (80%)          CROSS-DOMAIN CONTEXT (20%)
├─ Deal metrics               ├─ CSM health score
├─ Pipeline value             ├─ Finance contract terms
├─ Sales cycle                ├─ Support ticket count
├─ Win rates                  └─ Marketing campaign source
└─ Quota progress

All contextual data is:
  ✓ Real-time (pulls from live Spine)
  ✓ Abstracted (only shows what matters)
  ✓ Actionable (one-click navigation)
  ✓ Compact (sidebar widget, not overwhelming)
  ✓ Read-only (stay in primary domain to edit)

HOW IT WORKS: THE ENGINE
─────────────────────────────────────────────────────────────────────────────

Step 1: Sales rep views a deal

Step 2: Workbench calls engine:
  context = OrganizationalContextEngine.getEntityContext(
    entity_id: 'deal_123',
    entity_type: 'DEAL',
    requesting_domain: 'sales',
    spine_data: allSpineRows
  )

Step 3: Engine returns:
  {
    primary: [deal_123 full row],
    secondary_context: {
      csm: [{
        account_health_score: 85,
        nrr_contribution: 15000,
        churn_probability: 0.05
      }],
      finance: [{
        contract_terms: '2 year, $50k ARR',
        payment_status: 'current',
        mrr: 4166
      }],
      support: [{
        open_incident_count: 1,
        satisfaction_score: 4.5,
        avg_response_time: '2h'
      }],
      marketing: [{
        campaign_source: 'Webinar Q3 2025',
        lead_quality_score: 8.5
      }]
    },
    cross_domain_actions: [
      'csm:view_account_health',
      'finance:view_contract_details',
      'support:view_related_incidents',
      'marketing:view_campaign_attribution'

Step 4: Component renders context sidebar:

KEY DESIGN PRINCIPLES
─────────────────────────────────────────────────────────────────────────────

✓ 80/20 Split
  Primary domain gets 80% of workbench space
  Cross-domain context gets 20% in sidebar

✓ Proper Abstraction
  Sales doesn't see all CSM data, just health_score + churn_risk
  CSM doesn't see all Sales metrics, just pipeline + upsell_potential
  Each domain sees ONLY what it needs to make decisions

✓ One-Click Navigation
  Every cross-domain context has a button to "View in [Domain]"
  Navigation preserves context (breadcrumbs, back button)
  No lost context when switching domains

✓ Real-Time Data
  Cross-domain data pulls from live Spine
  Refreshes with main metrics
  Shows freshness indicator

✓ Graceful Degradation
  If domain not connected, shows "Connect [tool] to unlock [data]"
  Never displays broken data
  Context quality score visible

✓ Read-Only Secondary
  Cross-domain data is read-only
  To edit, must navigate to owner domain
  Prevents accidental changes in wrong domain

SCALING TO ALL 12 WORKBENCHES
─────────────────────────────────────────────────────────────────────────────

Pattern is identical for all workbenches. To add cross-domain context to any workbench:

1. Import in workbench component:
   import { OrganizationalContextEngine } from './foundation/org-context';
   import { CrossDomainContext } from './components/cross-domain-context';

2. Add props:
   crossDomainContext?: {
     secondary_context?: Record<string, SpineRow[]>;
     cross_domain_actions?: string[];
   };

3. Compute context (in render):
   const context = OrganizationalContextEngine.getEntityContext(
     selected_entity_id,
     entity_type,
     'your_domain_name',
     spine_data
   );

4. Render sidebar:
   {context && (
     <CrossDomainContext
       current_domain="your_domain"
       secondary_context={context.secondary_context}
       cross_domain_actions={context.cross_domain_actions}
       onCrossDomainNavigate={handleNavigation}
     />
   )}

Time per workbench: ~15 minutes
Total for all 12: ~3 hours

USAGE EXAMPLE
─────────────────────────────────────────────────────────────────────────────

In your page/route:

import {
  SalesRevOpsWorkbench,
  OrganizationalContextEngine,
  METRICS_BY_DOMAIN,
} from '@integratewise/domain-shells/workbenches';
import { useRouter } from 'next/navigation';

export default function SalesPage() {
  const router = useRouter();
  const spineRows = useSpineRows('sales'); // Get from your backend
  
  // Compute metrics
  const metrics = METRICS_BY_DOMAIN.sales_revops.map(m =>
    MetricEngine.computeMetric(m, spineRows)
  );

  // Compute cross-domain context
  const spineDataMap = new Map([
    ['spine_deals', spineRows],
    ['spine_accounts', csmSpineRows],
    ['spine_invoices', financeSpineRows],
    // ... all spine tables
  ]);

  const context = OrganizationalContextEngine.getEntityContext(
    selected_deal_id,
    'DEAL',
    'sales',
    spineDataMap
  );

  return (
    <SalesRevOpsWorkbench
      metrics={metrics}
      dataQuality={dataQuality}
      crossDomainContext={context}
      onCrossDomainNavigate={(action) => {
        const [domain, ...] = action.split(':');
        router.push(`/workbench/${domain}?context=...`);
      }}
    />
  );
}
